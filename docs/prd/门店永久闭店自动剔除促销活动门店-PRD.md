## 三、背景与问题定义

### 3.1 背景说明

促销后台承载全量促销活动的配置与运营。活动普遍支持三种门店范围：

- **全部门店参与**
- **部分门店参与**（指定参与门店名单）
- **部分门店不参与**（指定不参与门店名单）

门店生命周期由门店主数据管理。本需求中，**「永久闭店」与后台门店状态「已停业」为同一业务含义**（选店器、列表展示均称「已停业」）。门店变为已停业后，不应再出现在上游对促销侧的可选门店集合中。

但历史已保存的活动配置中，若「指定参与」或「指定不参与」名单仍包含该门店：

- **指定参与**残留 → 占用活动范围，易导致编辑/复制/新建时「活动有冲突」，甚至整场作废重建（工单 GD260427136）。
- **指定不参与**残留 → 排除已停业门店无业务意义；若名单里**全是已停业**，配置失效且运营不易察觉。

### 3.2 问题陈述

> 当前品牌运营在门店变为已停业后，非终态促销活动的「指定参与 / 指定不参与」名单仍可能保留该门店；参与侧导致冲突与重建成本，不参与侧导致「排除名单全是已停业」的失效配置无人知晓，缺少自动清理与主动触达。

### 3.3 为什么现在做

- 已停业后门店残留依赖人工清理，成本高、易漏，已有工单反馈。
- 冲突误报会阻断正常新建/编辑/复制。
- 指定不参与名单「全是已停业」时配置已无意义，必须通过页面提示与站内信触达创建人。

### 3.4 目标用户与场景

| 用户/角色 | 场景 | 痛点 | 期望结果 |
|---|---|---|---|
| 活动创建人 / 品牌运营 | 门店已停业后维护非终态活动 | 要逐个活动删门店，易漏 | 系统自动从参与/不参与名单去掉该店 |
| 活动创建人 | 参与名单被剔空，或不参与名单剔空/全是已停业 | 不知道活动门店配置已失效 | 列表/详情有统一提示，并收到站内信 |
| 活动创建人 | 已停业后复制/编辑/新建活动 | 报「活动有冲突」 | 已停业门店不再占用有效参与范围 |
| 测试 / 运营支持 | 核对清理结果 | 不知哪些活动被改过 | 操作日志可追溯 |

## 四、目标与成功指标

### 4.1 产品目标

- 门店变为**已停业**后，系统自动从**全部非终态**促销活动的「**指定参与**」与「**指定不参与**」名单中移除该门店。
- 能力覆盖**正式产品定义的全部促销活动类型**（见 5.1.1）。
- 避免因已停业门店残留导致的活动冲突与整场作废重建。
- 当门店配置进入**失效态**（S1 / S2，见 6.6）：活动状态不擅自变更；**全类型统一前端提示**；向**活动创建人**发站内信。
- 选店交互：已停业门店不可被选入参与/不参与名单（与上游过滤一致）。
- 上线完成历史残留一次性补清。

### 4.2 非目标

- 本期不改写「全部门店参与」活动的配置（已停业由上游过滤，不进入有效集合）。
- 本期不对**已结束、已作废**等终态活动回写门店范围。
- 本期不因剔除门店而自动作废、自动暂停或自动结束活动。
- 本期不在门店重新营业后，自动将门店加回原活动。
- 本期不回溯修改历史订单、历史参与记录。
- 本期不改造消费者端优惠展示文案。
- 本期不新建独立「闭店清理任务中心」或闭店清理汇总报表。

### 4.3 成功指标

| 指标 | 当前值 | 目标值 | 统计口径 | 观测周期 |
|---|---|---|---|---|
| 已停业门店仍残留在非终态指定参与/不参与名单中的比例 | 依赖人工，易残留 | 自动清理后为 0 | 抽检 / 对账 | 上线验收 + 上线后 2 周 |
| 因已停业残留导致的「活动有冲突」工单 | 有（如 GD260427136） | 明显下降 | 工单 / 运营反馈 | 上线后 4 周 |
| 失效态（S1/S2）创建人触达率 | 无 | 进入失效态后创建人可收到站内信，列表可见标识 | 站内信发送成功 + 列表抽检 | 上线验收 |
| 自动剔除可追溯率 | 无统一日志 | 每次成功剔除均可在操作日志查到 | 抽检操作日志 | 上线验收 |

### 5.2 方案概述

门店状态变为**已停业**后，促销侧扫描该品牌下全量活动类型的**非终态**活动：

- 若为**指定参与**且名单含该店 → 从参与名单移除；
- 若为**指定不参与**且名单含该店 → 从不参与名单移除；
- 写入系统操作日志。

「全部门店参与」不改写配置。终态活动不回写。

清理后若进入**失效态**（见 6.6）：

- **S1**：指定参与且有效参与门店为 0 → 统一列表/详情提示 + 创建人站内信；状态不变；发布须重新选店。
- **S2**：指定不参与且不参与名单为空 → 业务上等同「未排除任何门店」（接近全部门店参与）；统一提示 + 创建人站内信；**不强制**改写为「全部门店」模式，但文案须说清含义；状态不变。

上线须对历史已停业残留做一次性补清，规则与日常一致。

### 5.3 用户旅程 / 业务流程

1. 门店在主数据中变为**已停业**。
2. 系统触发促销侧清理。
3. 扫描：非终态 +（指定参与或指定不参与）+ 名单含该店。
4. 从对应名单移除该店；写操作日志。
5. 若进入 S1 或 S2：展示统一前端标识；向活动创建人发站内信。
6. 创建人通过站内信或列表进入活动，补选门店 / 调整范围，或自行作废。
7. 冲突校验不再将被已停业门店计入有效参与范围。

### 5.4 关键假设

| 假设 | 验证方式 | 若不成立的影响 |
|---|---|---|
| 本需求触发状态「已停业」即原需求所述永久闭店，与选店器「已停业」一致 | 与门店主数据确认 | 状态映射错误会导致误剔或漏剔 |
| 已停业门店在上游门店列表请求中已被过滤 | 联调 | 选店仍可能选到已停业，需促销侧双保险禁止勾选 |
| 各活动类型终态定义清晰（有「已结束」则跳过已结束+已作废；无则至少跳过已作废） | 状态机对齐 | 漏剔或误剔 |
| 冲突判断使用清理后的有效参与门店 | 规则评审 | 清名单后仍可能误报冲突 |

### 6.2 自动剔除（核心）

#### 6.2.1 功能描述

门店变为已停业后，系统自动将其从所有非终态促销活动的「指定参与」「指定不参与」名单中移除。

#### 6.2.2 前置条件

- 门店状态成功变为**已停业**。
- 存在至少一个非终态、且指定参与或不参与名单包含该门店的促销活动。

#### 6.2.3 入口与触发

| 入口 | 触发条件 | 展示规则 |
|---|---|---|
| 系统自动 | 门店变为已停业 | 无额外确认；结果通过日志/提示/站内信可见 |
| 活动列表 / 详情 / 操作日志 / 消息中心 | 清理完成后 | 展示更新后的名单、失效态标识、系统日志、站内信 |

> 无「手动一键清理」独立入口。上线**必须**一次性补清（见 10.2）。

#### 6.2.4 主流程

1. 门店变为已停业。
2. 确定范围：该品牌、5.1.1 全部活动类型、非终态活动。
3. 若「指定参与」含该店 → 从参与名单移除。
4. 若「指定不参与」含该店 → 从不参与名单移除。
5. 写操作日志（含门店可识别信息、移出的是参与还是不参与名单）。
6. 判定是否进入 S1 / S2；若是 → 前端标识 + 向创建人发站内信。
7. 清理完成；该店不再作为有效参与门店享惠或参与冲突计算。

#### 6.2.5 分支与异常流程

| 场景 | 触发条件 | 系统处理 | 用户反馈 |
|---|---|---|---|
| 终态活动 | 已结束 / 已作废等 | 不改名单 | 无 |
| 全部门店参与 | — | 不改写配置 | 无 |
| 指定参与含该店，剔除后仍有营业门店 | — | 更新名单 + 日志 | 参与门店数减少 |
| 指定参与剔除后为空 | S1 | 状态不变；S1 标识；站内信 | 见 6.4、6.5 |
| 指定不参与含该店，剔除后仍有其他店 | — | 更新名单 + 日志 | 不参与门店数减少 |
| 指定不参与剔除后为空 | S2 | 状态不变；不强制改模式；S2 标识；站内信 | 见 6.4、6.5 |
| 存量：不参与名单非空但全是已停业 | S3 | 补清时应剔光并收敛为 S2；补清前列表可展示 S3 | 见 6.6 |
| 名单不含该店 | — | 跳过 | 无 |
| 重复触发 | 幂等 | 已不在名单则跳过 | 无打扰 |
| 门店重新营业 | — | **不**自动加回 | 需运营重配 |
| 并发编辑 | — | 以清理后名单为准；不得再保存已停业门店进名单 | 见 R12 |
| 类型无门店名单 | — | 标注不适用 | 验收清单写出 |

> 设计：失效标识可扫视、非阻断弹窗；避免误以为已被系统作废。参与侧与不参与侧文案区分，样式体系统一。

#### 6.2.8 文案要求

| 场景 | 类型 | 文案 | 按钮 |
|---|---|---|---|
| 列表 S1 | 标签 | 有效参与门店为 0 | — |
| 列表 S2 | 标签 | 不参与门店已清空 | — |
| 列表 S3（补清前可选） | 标签 | 不参与门店均已停业 | — |
| 详情 S1 | 说明 | 参与门店已清空（含因门店已停业被系统自动移出）。请重新选择参与门店，或作废本活动。 | — |
| 详情 S2 | 说明 | 不参与门店已清空（含因门店已停业被系统自动移出）。当前未排除任何门店，效果接近「全部门店参与」。请确认是否需重新指定不参与门店，或调整门店范围。 | — |
| 操作日志：移出参与 | 日志 | 因门店已停业，系统自动移出参与门店「{门店名称}（{门店编码}）」 | — |
| 操作日志：移出不参与 | 日志 | 因门店已停业，系统自动移出不参与门店「{门店名称}（{门店编码}）」 | — |
| 操作日志：进入 S1 | 日志 | 移除后参与门店名单已为空，活动状态未变更 | — |
| 操作日志：进入 S2 | 日志 | 移除后不参与门店名单已为空，活动状态未变更 | — |
| 发布 S1 | 校验 | 请至少选择一个参与门店 | — |
| 站内信 | 见 6.4 | 见 6.4 | 见 6.4 |

#### 6.2.9 验收标准

- Given 门店 A 变为已停业，活动为指定参与且含 A，When 清理完成，Then 参与名单不含 A，有日志。
- Given 门店 A 变为已停业，活动为指定不参与且含 A，When 清理完成，Then 不参与名单不含 A，有日志。
- Given 终态活动名单含 A，When A 已停业，Then 名单不变。
- Given 全部门店参与，When A 已停业，Then 活动配置不被改写。
- Given 指定参与仅含 A，When 清理后，Then 进入 S1：状态不变、列表/详情有 S1 标识、创建人收到站内信、发布被拦截。
- Given 指定不参与仅含 A（或剔后为空），When 清理后，Then 进入 S2：状态不变、有 S2 标识、创建人收到站内信；不强制改门店模式。
- Given 付费会员价等非已作废状态，When A 已停业且在名单中，Then 须剔除。
- Given 5.1.1 非原型类型，When 同上，Then 正式产品须同样剔除。
- Given 仅因已停业门店 A 导致冲突，When A 被剔除后范围不再重叠，Then 可正常发布。
- Given 门店重新营业，When 无运营改配，Then 不自动回到名单。
- Given 历史订单含 A，When 清理，Then 历史不回溯。
- Given 选店，When 打开门店列表，Then 已停业不可选中。
- Given 上线补清，When 参与或不参与名单仍含已停业门店，Then 按日常规则清理并处理 S1/S2。

### 6.3 与活动冲突的关系说明

#### 6.3.1 功能描述

保证已停业门店不再计入非终态活动的有效参与门店，避免冲突误报。

#### 6.3.2 业务规则

| 规则编号 | 规则说明 | 备注 |
|---|---|---|
| C1 | 冲突门店范围 = 清理后的有效参与门店 | 指定参与读当前名单 |
| C2 | 全部门店的有效门店不含已停业（上游过滤/生效判定） | 不改写配置 |
| C3 | 不改变「哪些状态参与冲突」的既有规则，只保证名单正确 | 如草稿不参与冲突等 |

#### 6.3.3 验收标准

- Given 旧活动指定参与含已停业门店 A 且仅因此与新活动冲突，When A 被剔除后，Then 新活动不再因 A 失败。

### 6.4 失效态站内信（本期 P0）

#### 6.4.1 功能描述

活动因已停业清理进入 **S1 或 S2** 时，向**活动创建人**发送站内信。

#### 6.4.2 前置条件

- 本次清理（或补清）使活动新进入 S1 或 S2。
- 活动存在可识别的创建人。

#### 6.4.3 接收人规则

| 规则 | 说明 |
|---|---|
| 接收人 | **仅活动创建人** |
| 不发给 | 品牌全员、其他编辑人、闭店操作人（除非即创建人） |
| 创建人无法投递 | 失败可监控重试；不改发给他人 |
| 多活动多创建人 | 按创建人分别投递，只含自己名下活动 |

#### 6.4.4 触发与频控

| 规则 | 说明 |
|---|---|
| 触发 | 活动新进入 S1 或 S2 |
| 不触发 | 仅移除部分门店未进入失效态；终态未改 |
| 合并 | 同一已停业事件下，同一创建人名下多个 S1/S2 活动 → **1 条摘要**（正文区分参与清空 / 不参与清空）；不同创建人各自一条 |
| 幂等 | 同一活动同一失效结果不重复刷屏 |

#### 6.4.5 主流程

1. 清理完成，汇总本批进入 S1/S2 的活动。
2. 按创建人分组。
3. 单活动发单条；多活动发合并摘要（可同时含 S1 与 S2，文案分组列出）。
4. 创建人于消息中心查看并跳转活动。

#### 6.4.6 文案要求

| 场景 | 标题 | 正文 | 操作 |
|---|---|---|---|
| 单活动 S1 | 促销活动参与门店已清空 | 门店「{门店名称}」已停业，系统已将其从您创建的活动「{活动名称}」的参与门店中移出，当前有效参与门店为 0。活动状态未变更。请尽快重新选择参与门店，或作废该活动。 | 查看活动 |
| 单活动 S2 | 促销活动不参与门店已清空 | 门店「{门店名称}」已停业，系统已将其从您创建的活动「{活动名称}」的不参与门店中移出，当前不参与名单为空（未排除任何门店）。活动状态未变更。请确认是否需重新配置。 | 查看活动 |
| 同创建人多活动合并 | 多个促销活动门店配置需处理 | 门店「{门店名称}」已停业，您创建的以下活动门店配置已失效（状态未变更）：参与门店已清空：{列表}；不参与门店已清空：{列表}。请尽快处理。 | 查看详情 |

#### 6.4.7 验收标准

- Given 1 个活动进入 S1，When 发信，Then 仅创建人收到 S1 文案。
- Given 1 个活动进入 S2，When 发信，Then 仅创建人收到 S2 文案。
- Given 创建人甲 1 个 S1 + 1 个 S2，乙 1 个 S1，When 发信，Then 甲 1 条合并、乙 1 条单活动；互不可见对方活动。
- Given 未进入失效态，When 清理完成，Then 不发失效态站内信。
- Given 补清导致进入 S1/S2，When 完成，Then 同样发信（去重生效）。

### 6.5 失效态统一视觉规范（本期 P0）

#### 6.5.1 功能描述

非终态活动进入 S1/S2（及补清前 S3）时，全部活动类型列表与详情使用统一视觉体系、区分文案。

#### 6.5.2 规范要求

| 位置 | 必须具备 | 统一要求 |
|---|---|---|
| 活动列表 | 可扫视标签 | S1/S2/S3 文案见 6.2.8；样式体系一致，可用不同标签色区分类型（设计定） |
| 详情 / 预览 / 快照 | 空态或失效说明 | 使用对应详情文案 |
| 门店摘要列 | 与标识同时出现 | 不得只显示「0」而无原因 |

#### 6.5.3 显隐逻辑

| 条件 | 展示 |
|---|---|
| 非终态 + S1 | 展示 S1 |
| 非终态 + S2 | 展示 S2 |
| 非终态 + S3（不参与名单非空且全是已停业，补清前） | 展示 S3；补清后应变 S2 或恢复正常 |
| 指定参与且名单含营业门店 | 不展示失效标识 |
| 指定不参与且名单含营业门店 | 不展示失效标识 |
| 全部门店 | 不展示本标识 |
| 终态 | 不强制套用（不因本需求改名单） |

#### 6.5.4 验收标准

- Given 不同类型出现 S1/S2，When 打开列表，Then 文案与样式体系一致。
- Given 抽检 5.1.1 已上线类型，When 对照设计稿，Then 无缺标识类型。

### 6.6 失效态定义（S1 / S2 / S3）

| 编码 | 条件 | 业务含义 | 前端 | 站内信 | 活动状态 |
|---|---|---|---|---|---|
| **S1** | 指定参与，且参与名单数量 = 0 | 无有效参与门店 | 必须 | 必须（创建人） | 不变 |
| **S2** | 指定不参与，且不参与名单数量 = 0 | 未排除任何门店，接近全店参与 | 必须 | 必须（创建人） | 不变 |
| **S3** | 指定不参与，名单数量 ≥ 1，且名单内门店**全部为已停业** | 排除配置已失效（存量/补清前） | 必须（或补清后不再出现） | 补清收敛为 S2 时按 S2 发信 | 不变 |

> 日常触发若严格执行「从不参与名单移除已停业」，S3 会收敛为 S2。S3 用于补清前展示与测试兜底。

### 11.2 状态处理矩阵（摘要）

> 口诀：**只有「已经彻底结束」的活动不剔，其他都剔。**

| 无「已结束」的类型（如付费会员价） | 除已作废外全部要剔 |
