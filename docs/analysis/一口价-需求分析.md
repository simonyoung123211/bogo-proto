## 1. 背景与问题

运营需要配置「凑满指定件数，整组按打包价结算」的促销，典型话术如「3 件卤鸭腿 9.9 元」。

| 现有能力 | 能做什么 | 做不到什么 |
|---|---|---|
| 第 N 件优惠 / 满 M 件 N 件优惠 | 凑满件数后，对其中 N 件做折扣 / 立减 / 特价 | 不能把「整组 M 件」合成一个打包票价 |
| 会员价 / 储值支付优惠中的「一口价」 | 单品固定价 | 不是「满件数打包价」活动类型 |
| 满减/折 | 满金额 / 满件数后立减或打折 | 优惠语义是减/折，不是打包票价 |

因此需要独立活动类型「一口价」，规则语义是打包票价，而不是「其中某几件特价」。

## 2. 目标与非目标

### 2.1 目标
- 营销活动下新增「一口价」入口（列表 + 创建/编辑/查看向导）。
- 核心规则：活动商品达到配置件数后，对应件数按打包一口价结算（可配多级阶梯）。
- 优惠方式仅支持特价（打包价），不开放折扣、立减。
- 配置流程四步：基础信息与规则 → 参与门店 → 参与商品 → 预览/提交保存。
- 生命周期、暂停/恢复、共享互斥、渠道与业务场景等通用能力对齐现有活动。

### 2.2 非目标（本期）
- 不做真实优惠引擎与生产结算对接（原型阶段 Mock 演示即可）。
- 不把「一口价」并入第 N 件优惠的规则类型。
- 本期不做消费者端 Demo，仅在 PRD 中约定对客表现。
- 不做「每满 M 件」循环打包。
- 计件范围不做成配置项。

## 3. 核心业务语义

顾客购买的活动商品件数达到门槛 M 后，这 M 件合计按一口价 N 元结算，而不是对其中某几件单独打折。

| 对比项 | 第 N 件 / 满 M 件 N 件优惠（特价） | 本需求「一口价」 |
|---|---|---|
| 示例配置 | 满 3 件，其中 1 件特价 9.9 元 | 满 3 件，打包一口价 9.9 元 |
| 顾客理解 | 第 3 件只要 9.9 | 这 3 件一共只要 9.9 |
| 优惠方式 | 折扣 / 立减 / 特价 | 仅打包特价 |
| 计件 | 可按同商品或跨商品配置 | 固定任意活动商品合计，不可配置 |

计价示意（原价 12 元/件，满 3 件一口价 9.9 元）：1～2 件原价；3 件合计 9.9 元；4 件为 9.9 元 + 原价 1 件（阶梯就高、非循环）。若同时配置满 5 件一口价 15 元，买 5 件按 15 元，买 4 件仍按满 3 件的 9.9 元 + 1 件原价。

## 4. 方案概述

列表 → 新建 → ① 基础信息 / 优惠规则（阶梯打包价，仅特价）→ ② 参与门店 → ③ 参与商品 → ④ 预览并保存。

交互壳、字段密度、门店/商品选择器复用现有活动向导；规则区为「满 M 件，N 元」阶梯，参考满减阶梯的增减与校验体验。

## 5. 功能说明

### 5.1 列表
- 侧栏「营销活动」下增加「一口价」。
- 状态 Tab、筛选、新建、编辑/复制/发布/暂停/恢复/作废、草稿删除、查看，对齐同类活动。
- 列表摘要展示规则，如 `满3件一口价9.9元`；多级时列出各级，级数较多时展示「N 级阶梯」及最高阶。

### 5.2 步骤 1 基础信息与规则
- 范围：参与渠道（多选，至少 1）、参与业务场景（多选，至少 1）。
- 基础信息：活动名称、标题、活动说明、有效时间、活动频次（每天/每周/每月）、参与时段（全天/指定时间段）。
- 优惠规则：
  - 条件固定为满件数。
  - 方式锁定为打包一口价（特价），界面不出现折扣、立减选项。
  - 阶梯 `满 [M] 件，合计 [N] 元`，最多 10 级。
  - 下一级件数须大于上一级，下一级金额须高于上一级。
  - 计件范围固定为任意活动商品合计，只展示说明，不做配置项。
  - 命中方式固定为阶梯就高，不做每满循环。
- 限购与次数：每订单可享受打包组数；每人活动期间限购单数；每人按天/周/月限购单数。
- 高级选项：共享/互斥、参与用户、打标签、活动权重、活动编码、点单页标题是否展示。

### 5.3 步骤 2 参与门店
全部门店 / 指定门店参与 / 指定门店不参与；已选列表与统计复用现有门店选择。

### 5.4 步骤 3 参与商品
只选参与商品，展示商品信息、规格、原价。不在单品行配置折扣、立减或单品一口价，也不做「一口价 / 原价」单选。支持全部商品或指定商品，指定时可正选或反选。

### 5.5 步骤 4 预览并保存
汇总基础信息、规则摘要、门店范围、商品清单。可保存草稿，或保存后回到列表再发布。口径对齐现有活动：新建保存后为待发布，已发布活动再次保存保持原状态。

## 6. 两端联动
- 商家端：品牌/运营在促销后台配置一口价活动、门店与商品。
- 消费者端（仅约定，本期不做 Demo）：点单页/购物袋展示促销标签与规则文案（如「3 件 9.9」）；达件数后按打包价重算。详见 PRD。
- 无有效活动走原价；件数不足、门店或渠道不匹配则不享受。
- 新活动类型，不影响存量活动数据。

## 7. 验收要点
- 可新建「满 3 件一口价 9.9」并选门店、商品后保存。
- 规则校验：阶梯件数与金额递增；优惠方式不可选折扣/立减；计件范围不可配置。
- 列表可见规则摘要；详情/预览与配置一致。
- 与「满 3 件其中 1 件特价 9.9」在文案与规则摘要上可区分。
