# 储值支付优惠 · 需求分析

## 1. 背景与问题

品牌希望引导顾客使用商家储值余额支付。现有会员价可配置商品优惠力度，但无法把「必须用储值余额支付」作为享受优惠的资格条件。运营需要一种与会员价配置体验接近、但资格绑定储值支付的活动类型。

## 2. 目标与非目标

### 2.1 目标

- 新增活动类型「储值支付优惠」。
- 商品优惠配置能力对齐会员价（折扣 / 立减 / 一口价）。
- 活动级单选两种支付参与规则，限制顾客须用储值余额支付才可享受。
- 提供通用设置：促销标签、整单余额支付参与门槛。
- 生命周期对齐现有活动：草稿、暂停/恢复、状态 Tab 统一顺序。
- 本期原型补齐渠道 / 业务类型 / 叠加 / 展示 / 权重等基础字段；其他活动类型后续按同一字段口径迭代补全。

### 2.2 非目标

- 本期不做真实支付扣款、余额账户对接与生产优惠引擎。
- 本期不做门店层级 / 门店标签选店（沿用现有门店选择器）。
- 本期不做跨活动类型混合参与记录明细（参与记录可先占位，口径与其他类型一致）。

## 3. 角色与场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 品牌运营 | 配置储值专享价拉动充值与余额消耗 | 能建活动、选规则、配商品价、设门店 |
| 品牌运营 | 调整整单余额门槛口径 | 在通用设置中切换「原价小计 / 优惠前应付 / 优惠后应付」 |
| 顾客（对客约定） | 点单结算 | 仅当支付方式满足活动规则时享受活动价 |

## 4. 方案概述

在营销活动下新增「储值支付优惠」入口，整体流程参考支付优惠 / 会员价：

1. 活动基础信息与规则（含支付参与规则）
2. 设置参与门店
3. 设置参与商品及优惠
4. 预览并保存

另设「储值支付通用设置」页，作用于该活动类型全局。

## 5. 功能说明

### 5.1 列表

- 能力对齐会员价列表：筛选、状态 Tab、新建、通用设置、编辑/复制/发布/暂停/恢复/作废、草稿删除。
- 列表需展示支付规则摘要（如「余额支付≥0.01」或「整单仅余额」）。

### 5.2 向导 · 步骤 1 基础信息与规则

#### 范围渠道（补全口径）

- 适用渠道：手机网页、微信小程序、支付宝小程序、App、POS、抖音小程序、第三方外卖等（可多选，至少 1 个）。
- 业务类型：堂食、外卖（平台配送）、外卖（商家自配送）、自提等（可多选，至少 1 个）。

#### 基础信息

- 活动名称（必填）
- 活动摘要 / 点单页展示标题
- 商品促销标签
- 活动备注（对内，不对客）
- 生效时间（起止，必填）
- 活动周期：每天 / 每周 / 每月
- 活动时段：全天 / 指定时间段
- 活动说明

#### 支付参与规则（活动级单选，必填）

| 选项 | 业务判定 | 对客说明示例 |
|---|---|---|
| 储值余额支付 ≥ 0.01 即可参与 | 本单储值余额实付金额 ≥ 0.01 元即可享受活动价 | 使用储值余额支付满 0.01 元可享 |
| 整单仅限储值余额支付才可参与 | 本单应付金额须全部由储值余额支付，才可享受活动价 | 整单使用储值余额支付可享 |

规则选定后不可多选并存；复制活动时继承原规则，可再改。

#### 优惠与限制（对齐会员价）

- 商品优惠方式在步骤 3 配置；步骤 1 可保留次数/件数类限制（总次数、频次、活动期/每日/每单件数），口径与会员价一致。
- 加料 / 套餐加价 / 做法加价是否参与优惠：与会员价一致开关。

#### 叠加及配置

- 叠加情况：不叠加 / 与指定类型共享或互斥（沿用现有共享互斥组件口径，可先做「不共享 / 共享」简化展示，字段预留完整）。
- 支付限制：本活动固定为「仅储值余额支付可享」；界面展示只读说明，不开放选微信/支付宝等其他支付方式作为享受条件。
- 列表/详情页促销标签展示：展示 / 隐藏。
- 活动权重（排序优先级）：数值越大越优先（演示字段）。

### 5.3 向导 · 步骤 2 参与门店

- 全部门店 / 部分门店参与 / 部分门店不参与（现有门店选择器）。
- 已选门店展示营业状态。

### 5.4 向导 · 步骤 3 参与商品及优惠

与会员价一致：

- 优惠方式：折扣 / 立减 / 一口价
- 商品范围：全部商品 / 部分商品（含反选）
- 逐商品优惠值、已选商品检索、分页、批量设置与批量移除
- **不展示会员等级选择**（资格来自储值支付，不是会员等级）

### 5.5 向导 · 步骤 4 预览保存

- 汇总展示：规则、门店、商品优惠、限制、叠加与展示配置。
- 操作：取消、上一步、保存草稿、发布/保存。

### 5.6 通用设置

| 配置项 | 选项 | 说明 |
|---|---|---|
| 定制商品促销标签 | 系统默认 / 定制促销标签内容和样式 | 定制后可配置文案、样式与预览 |
| 商品促销标签 | 系统默认「储值享」/ 取当前会员等级名称 / 自定义（≤10 字） | 取值优先级：活动内标签 > 通用设置自定义 > 系统默认 |
| 定制样式 | 默认样式 / 自定义样式 | 自定义可选纯色或图片背景；左侧文案、右侧价格分别配色 |
| 整单余额支付活动参与条件 | 用户余额 ≥ 订单原价小计；用户余额 ≥ 本活动优惠前应付；用户余额 ≥ 本活动优惠后应付 | **仅当活动规则为「整单仅限储值余额支付」时生效**；默认「优惠后应付」 |

口径说明（对运营可见）：

- 订单原价小计：购物车商品原价合计（门槛最高）。
- 本活动优惠前应付：扣除本活动之前已生效优惠后的应付小计，不含本活动优惠。示例：原价 20 元，限时折扣已减 3 元且与本活动共享，则余额须 ≥ 17 元。
- 本活动优惠后应付：再扣除本活动优惠后的应付金额（门槛最低，品牌推荐）。示例：原价 20 元，限时折扣已减 3 元，本活动再减 2 元，则余额须 ≥ 15 元即可参与。

门槛从高到低：原价小计 > 优惠前应付 > 优惠后应付。规则为「余额支付 ≥ 0.01」的活动，不受该门槛配置约束。

## 6. 业务规则

| 编号 | 规则 |
|---|---|
| R1 | 支付参与规则为活动级单选，必填。 |
| R2 | 顾客未按规则使用储值余额支付时，不享受本活动价，回退其他可用优惠或原价。 |
| R3 | 商品优惠方式与校验对齐会员价。 |
| R4 | 草稿可半成品保存（至少活动名称）；发布需通过各步校验。 |
| R5 | 进行中可暂停；暂停不对客生效；有结束时间且暂停中到期 → 已结束。 |
| R6 | 通用设置中的整单余额门槛，只影响规则 2 活动。 |
| R6.1 | 整单门槛三档：原价小计 / 优惠前应付 / 优惠后应付；判定时用户储值余额须 ≥ 所选口径对应金额。 |
| R7 | 渠道与业务类型至少各选 1 项。 |

## 7. 状态与操作

复用通用活动状态：草稿 → 待发布 / 未开始 / 进行中 / 已暂停 / 已结束 / 已作废。  
列表操作与会员价一致。

## 8. 验收要点

- 可创建储值支付优惠，两种支付规则只能选其一。
- 商品步可配置折扣/立减/一口价，支持已选检索。
- 通用设置可保存标签（文案三选一、默认/自定义样式、纯色或图片）与整单余额三档门槛；默认「优惠后应付」。
- 暂停/恢复、草稿保存与发布路径可用。
- 渠道与业务类型选项已按补全口径展示。

## 9. 开放问题（已确认）

| 问题 | 结论 |
|---|---|
| 商品优惠是否对齐会员价 | 是 |
| 两种支付规则关系 | 活动级单选 |
| 渠道/业务等字段 | 本期补全；其他活动后续迭代对齐 |
| 交付节奏 | 先需求分析，再原型 |
